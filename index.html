First verified path

From local artifact to import receipt

Use the narrow path first. Inspect metadata, verify the user-owned artifact, then produce a receipt that binds what Rust accepted.

Hard constraint

Project servers carry metadata, never user model bytes

This boundary keeps MiniModel a discovery and verification ecosystem instead of a hidden hosting or inference service.

  • AllowedStatic documentation, schemas, example manifests, metadata catalogs, public-key routes, signed snapshots, and contact or takedown routes.
  • Not allowedThird-party .slm, safetensors, GGUF, ONNX, adapter, tokenizer, or peer-piece payloads served from project infrastructure.
  • No proxy laneNo Hugging Face proxy, peer-transfer relay, browser download proxy, or project-hosted user inference.
  • Local authorityTinyRustLM opens a user-selected local file. Rust/WASM validates the bytes before use.
  • Claim boundaryCatalog rows are publisher assertions and evidence pointers, not project endorsements or legal opinions.

Binary contract

The .slm v1 container

A narrow little-endian model format gives the runtime a bounded parser, an explicit tensor inventory, and deterministic rejection behavior.

Container layout

Fixed, aligned, and checksum bound

The file begins with SLM1, carries a 108-byte v1 header, tokenizer metadata, one 64-byte directory entry per tensor, aligned payloads, and a u64 checksum recomputed with bytes 100 through 108 treated as zero.

Acceptance authority

Rust decides what can load

JavaScript may display progress and routes. Rust rejects unsupported versions, shape drift, offset escapes, malformed tokenizers, unsupported dtypes, invalid scales, checksum drift, and missing required tensors.

Portable evidence

MiniModel manifest v0

The line-oriented key=value document binds publisher assertions and evidence to a user-supplied artifact. It never authorizes a project server to fetch model bytes.

  • Identity: model, publisher, license, and model-card routes.
  • Artifact: kind, exact byte count, SHA-256, and no-project-server declaration.
  • Runtime: format version, shape, quantization, tokenizer, and tensor layout.
  • Exchange: chunking, Merkle evidence, peer sources, and signature identity.

Local Rust workflow

Parse, prove, then write a receipt

Every workflow ends at the same authority: the receiver verifies local bytes and retains evidence that can be inspected later.

01

Parse

Reject duplicates, unsupported schema versions, missing fields, unsafe keys, and noncanonical signed input.

02

Prove

Verify byte count, SHA-256, chunks, Merkle root, structure, tokenizer, tensor layout, and runtime compatibility.

03

Receipt

Bind accepted bytes to the saved request, preflight, peer metadata, transfer evidence, and receiver validation.

Acquisition boundaries

Three source lanes, one verifier

Discovery changes where metadata comes from. It never changes who must verify the final local bytes.

Available now

Your local files

Bring a local .slm artifact and optional sidecars. Rust verifies the local path; TinyRustLM opens the same user-selected file.

External discovery

Hugging Face

Model cards and source-file hints can create local conversion handoffs. MiniModel does not proxy downloads or make source metadata runnable.

Expanding lane

Known-peer exchange

Direct peer status, requests, preflight, pieces, receipts, and companion metadata preserve receiver-side verification without project-hosted bytes.
